# 耗材二维码出入库方案

## 目标与边界

每个耗材档案使用数据库中稳定、不随改名而变化的 UUID 生成二维码。二维码内容是当前站点的耗材直达网址，例如：

```text
https://inventory.example/?material=<耗材 UUID>
```

按库存单元追踪的耗材还可为每个盒、批次或序列生成独立二维码：

```text
https://inventory.example/?unit=<库存单元 UUID>
```

扫码只完成“识别并选择耗材”，不会直接增加或扣减库存。成员仍需登录，选择入库或出库，填写数量、来源或去向、发生时间和备注，最后明确保存。库存变化继续只通过现有事务接口产生不可变流水。

库存单元二维码同样只完成定位。扫码后显示该盒、批次或序列内的位置、状态、开放/自用归属和数量，由成员选择具体明细及操作后保存。

## 使用流程

### 生成和张贴标签

1. 登录后进入“库存管理”。
2. 点击耗材行右侧的二维码图标。
3. 核对名称、分类、规格、当前库存和内部 UUID。
4. 选择 `40 × 25 mm`、`50 × 30 mm`、`70 × 40 mm`、`86 × 54 mm`，或输入自定义标签尺寸。
5. 可下载完整标签 PNG、下载纯二维码 PNG，或直接打开浏览器打印选项。

完整标签不写入会变化的当前库存，避免库存变化后实体标签立即过期。预览、PNG 下载和打印共用同一张 Canvas 标签图，字体、换行和二维码比例保持一致；内容会按尺寸自动缩放，不另外提供会改变物理尺寸的二次缩放。自定义标签支持横向 `35–120 mm × 22–80 mm`，宽度至少为高度的 `1.4` 倍；小于推荐的 `40 × 25 mm` 时会提示文字与扫码风险。打印时选择“实际大小”或 `100%`，并关闭浏览器的页眉和页脚；标签 PNG 按 300 DPI 生成，适合交给常见标签编辑和打印软件继续排版。

打印排版支持“标签机 / 单张标签纸”和“A4 自动排版”。A4 模式填写当前耗材的打印份数后，会按标签毫米尺寸自动计算每行与每页数量，超出一页时自动分页；例如 `86 × 54 mm` 在默认 10 mm 页边距和 3 mm 间距下每页可排 8 个。完整标签 PNG 和标签机输出不带最外框，避免打印机不可打印边缘造成框线缺失；A4 模式可单独开关位于安全页边距内的浅色裁切辅助线。

库存页的“A4 批量打印标签”可搜索并勾选多个不同耗材、全选当前搜索结果、设置每种份数，并按选择顺序混排。批量打印与单耗材打印共用标签生成和 A4 分页逻辑，每批最多 100 张，防止手机浏览器生成大量高分辨率 PNG 时占用过多内存。
5. 将标签贴在耗材包装、货架或存放位置。

二维码绑定 UUID，不绑定名称、分类、规格或库存数量。之后修改这些显示信息不需要重印标签；永久删除档案后旧标签会失效。二维码同时包含生成时的站点域名，因此迁移域名时应保留旧域名跳转，或重新打印标签。

域名不是代码或二维码协议中的固定品牌。系统会使用用户打印标签时实际访问的地址生成绝对网址：部署在 `https://inventory.example.org` 时，新标签自然是 `https://inventory.example.org/?material=<UUID>`；部署在子路径时也会保留该路径。扫描解析不限定特定域名，品牌显示名称也不参与有效性判断，因此同一生产包可用于不同站点。

若把同一客户的数据库和现有实体标签从旧域名迁移到新域名，应至少在旧域名保留长期 `301` 或 `308` 跳转，并完整保留路径及 `material` 查询参数。若旧域名无法继续控制，已经印出的绝对网址无法自动发现新域名，只能重新打印标签。不同客户应使用独立数据库；即使两个客户使用相同程序包，也不能共享耗材 UUID 数据空间。

实例显示名称不参与二维码有效性判断。OpenLabStock 是默认产品显示名称；管理员修改左上角名称后，标签和扫描错误提示会使用新名称。二维码内部始终使用稳定 UUID，改名不会导致已有标签失效。

### 站内扫码登记

1. 点击总览、库存或流水页的“扫码登记”。
2. 选择入库或出库。
3. 使用摄像头扫描，或上传一张二维码图片。
4. 系统识别耗材后打开原有登记表单并预选耗材。
5. 用户核对数量和业务信息后保存。

在登记表单中点击“扫描二维码”时，已填写的数量、时间和备注会保留，扫码仅替换耗材选择。

### 使用手机系统相机

用手机系统相机扫描后会打开二维码中的网址。未登录时先进入登录页，登录成功后继续打开对应耗材的登记表单；已登录时直接进入。直达链接默认打开出库，但用户可以在表单顶部切换成入库。

扫描库存单元二维码时，登录后直接打开对应库存明细。已归档的空盒只能查看，不能登记；已永久删除耗材的库存单元二维码明确提示不存在。

## 异常处理

- 无效二维码：提示没有识别到有效耗材编号，不改变库存。
- 其他系统或已永久删除的耗材：提示当前系统中不存在，不改变库存。
- 无效、其他系统或已删除的库存单元：提示库存单元不存在，不改变库存。
- 已归档耗材：提示先恢复使用，不允许登记。
- 摄像头权限被拒绝或不可用：保留二维码图片识别入口。
- 图片超过 12 MB：提示压缩或裁剪后重试，避免手机浏览器占用过多内存。
- 重复扫描：一次打开流程只接受首个有效结果，随后立即停止摄像头。

## HTTPS、HTTP 与隐私

- 浏览器摄像头通常只允许 HTTPS 或 localhost 安全上下文使用。正式域名应保持 HTTPS。
- 使用 HTTP/IP 访问时，页面仍可登录、打开二维码直达链接和识别本地二维码图片，但不承诺浏览器摄像头可用。
- 服务端响应头只向同源页面开放摄像头：`Permissions-Policy: camera=(self)`。
- QR 生成和识别均在浏览器本地完成，不调用第三方二维码服务。
- 二维码中不包含账号、密码、会话 Cookie、库存数量或其他敏感业务数据。
- 耗材网址不能绕过登录和权限校验；会话令牌仍只存放在 HttpOnly Cookie 中。

## 参考项目与取舍

### LIME

[LIME (Laboratory Inventory Management Engine)](https://github.com/chsolis/lime_lab_inventory_management_engine) 使用电子表格与扫码工具结合：扫码定位物品，由用户明确记录增加或减少，并把变动写入日志。本系统采用了“扫码定位、人工确认、完整流水”的工作流，但没有复制其代码。该仓库公开许可证元数据不明确（`NOASSERTION`），因此只作为产品流程参考。

### eLabFTW

[eLabFTW](https://github.com/elabftw/elabftw) 将实体网址编码进二维码，并支持生成可打印标签。相关实现可见 `src/templates/qr-pdf.html`、`src/Services/MpdfQrProvider.php` 和 `src/Controllers/InventoryController.php`。本系统借鉴了“实体网址 + 本地生成 + 可打印标签”的设计，但没有复制代码；eLabFTW 使用 AGPL 许可证。

## 实现约束

- UUID 是二维码与耗材档案或库存单元的唯一绑定键，禁止改用可编辑名称、盒号或位置编号匹配。
- 识别成功后必须进入现有出入库表单，禁止扫码即写库存。
- 所有写入继续由后端校验登录、耗材状态、数量和库存余额。
- 已归档耗材不进入扫码登记；永久删除后历史流水继续保留名称和单位快照。
- 扫描库和二维码生成库保持动态加载，不能增加普通登录和首页刷新关键路径。
- Service Worker 不缓存二维码直达页面或库存写请求，也不离线排队。

## 发布验收

1. `pnpm run build`、`pnpm test`、`pnpm audit --prod` 全部通过。
2. 桌面和 `390 x 844` 手机视口中检查扫码弹窗、二维码标签弹窗、库存行操作和页面标题按钮无溢出。
3. 验证二维码 PNG 能被“识别二维码图片”读取，并打开正确耗材。
4. 验证 `/?material=<UUID>` 在已登录和未登录状态下都能继续到正确耗材，且地址参数消费后被移除。
5. 验证 `/?unit=<UUID>` 能打开正确盒、批次或序列，归档单元只读、无效和已删除单元返回明确错误。
6. 在正式 HTTPS 域名用 Android Chrome 和 iOS Safari 真机验证后置摄像头、拒绝权限、再次授权和切换后台后的摄像头释放。
7. 确认扫描过程没有直接生成流水，只有点击“保存记录”后库存才变化。
