# OpenLabStock Governance

OpenLabStock uses a maintainer-led model. Technical authority, repository permissions, copyright, trademarks, commercial licensing and business ownership are related but separate concepts.

## Roles

### Contributors

Contributors report issues, improve documentation, review designs or submit code. A contribution does not by itself create employment, partnership, equity, revenue sharing, ownership of the GitHub organization, trademark rights, or a right to a maintainer role.

Contributors retain the copyright they hold, subject to the repository license and any active contributor agreement they accepted.

### Maintainers

Maintainers triage Issues, review pull requests and protect project quality. Repository access is granted on least privilege and may be changed when responsibilities change. Maintainer status does not transfer the project steward's copyright, commercial rights, organization ownership or business interests.

Maintainers must disclose material conflicts of interest and recuse themselves where appropriate. Security reports, personal data and private operations information must remain confidential.

### Project Steward

The project steward sets the product direction, appoints maintainers, controls official releases and decides when consensus cannot be reached. Before public contributions are accepted under a CLA, the legally identified steward or licensing entity must be recorded in the operative agreement and private compliance records.

## Decisions

Routine changes are decided through review. Significant API, data-model, license, governance or security changes require a public Issue or decision record describing context, alternatives and consequences. Security incidents, contracts, personal data and unannounced commercial matters are handled privately.

Consensus is preferred, but it is not a veto system. The project steward makes the final decision after considering technical evidence, user impact, maintenance cost, license obligations and conflicts of interest.

## Releases

Official releases must originate from a protected tag, pass the repository verification workflow, include corresponding source and required notices, and publish checksums for distributed artifacts. A maintainer must not replace an existing release asset silently; corrections require a new version or an explicitly documented withdrawal.

## Changes to Governance

Material changes to this document should be proposed publicly before adoption. Changes cannot retroactively remove rights already granted under an open-source license or signed agreement.
